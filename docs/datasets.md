# Dataset provenance and connector status

| Source | In this release | Limitations |
|---|---|---|
| Seeded sea-ice scenes | Generated by `ml/train.py`; RF trained/evaluated; seed 26059 | Artificial generator, not satellite measurements |
| Seeded wind/current/temperature fields | Computed locally in `environment.py` | Simplified forcing assumptions, not meteorological forecasts |
| SIM-* iceberg observations | Locally generated positions with seeded noise | Fictional identities; no image detection or actual tracking feed |
| Vessel/mission | RV POLAR ONE and two fictional missions | No AIS, fuel sensor or real research-vessel deployment |
| Natural Earth Antarctica | Bundled `data/geography/antarctica.geojson` | Public-domain 1:110m reference polygon; not marine-chart resolution |
| Bharati station coordinate | Reference marker derived from NCPOR's station page | Coordinate reference only; not a navigation destination or landing route |
| NSIDC products | Documented integration target; NOT CONNECTED | Product/authentication/quality/time/projection handling not implemented |
| ERA5 / Copernicus Marine | Documented integration targets; NOT CONNECTED | No downloaded atmospheric/ocean products or automatic live adapter |
| CSV/JSON user observations | Validated preview overlay | Does not alter forecast/routing grid or model training |

- NSIDC NASA Team concentration product: https://nsidc.org/data/nsidc-0051/versions/2

- Copernicus Climate Data Store: https://cds.climate.copernicus.eu/
- Copernicus Marine: https://marine.copernicus.eu/

The supplied problem-statement ID, organization and title come from the user's brief. This release does not assert official SIH listing verification, NCPOR endorsement or an agency partnership.

The included Antarctica polygon was extracted from a locally available Natural Earth low-resolution reference fixture during the build. It is distributed as simple GeoJSON. `scripts/build_geography.py` can repack a compatible downloaded country shapefile when a developer supplies one and installs the optional pyogrio dependency. No shapefile package or geometry download is required for normal use.

## Why not pretend to connect everything?

Public products can differ in projection, grid cell semantics, temporal sampling, quality flags, licensing, availability and credentials. For example, a coarse daily concentration field cannot simply be relabeled as a high-resolution six-hour coastal navigation forecast. A reliable real-data pipeline needs explicit conversion, validation, data lineage and evaluation. Rather than showing green “live” badges for unavailable services, this prototype states which layers are simulated and which integrations remain future work.

## Real-data adapter design to implement next

1. Read an authorized product and preserve product/version/time/quality metadata.
2. Convert units and missing values before interpolation.
3. Align CRS and ocean/land masks; do not hallucinate coastal observations.
4. Resample with a method appropriate to the product and record the loss of resolution.
5. Synchronize issue time, valid time and forecast horizon.
6. Evaluate model-domain shift against real held-out observations before enabling routing.
7. Retain explicit stale/missing/out-of-coverage statuses and a human review path.

These are design requirements, not claims that an operational adapter has been implemented.
